# العقل المستقل لوكلاء INSCO

## ما نُفّذ

- نقاط `user-copilot` و`site-manager` و`community/assist` تعمل عبر قواعد محلية ومسار استرجاع من مكتبة الموقع، بلا استدعاء Gemini أو أي مفتاح خارجي. نسخة GitHub Pages تستخدم النواة نفسها محليًا في المتصفح.
- البحث يستخدم الفهرس العربي/الإنجليزي الحالي (132 مادة) وترتيب BM25 والمرادفات. لا يُعرض جواب تقني إلا بعد اجتياز حد الثقة القائم (`4.2` مع إشارات التغطية الحالية) وإشارة موضوع هندسي؛ عدا ذلك يمتنع عن التخمين. لم تُخفّض العتبة.
- كل رد يحدد نوع مصدره (`library` / `site-data` / `editorial` / `rules` / `decline`) و`model: null`. تُعرض الاستشهادات وخطوات البحث القابلة للتحقق. محلل الموقع يعتمد على أرقام التليمترية المرسلة، ولا يخترعها.
- المستشار يتابع أسئلة المستخدم السابقة، يستنتج بعض مقاصد الصياغة وطلبات RFQ، ويطلب بيانات الاختيار الفني الناقصة بدل إعطاء توصية بلا سياق. فحص الكود لا يعلن المطابقة؛ إما يعرض مرجعًا ذا صلة مع تحذير أو يمتنع عن التأكيد.
- سجل محادثة المستشار يُحفظ في `localStorage` على جهاز المستخدم لمدة 30 يومًا **لكل رسالة** (حد 300 رسالة)، مع زر لمسحه. لا يُرفع كسجل دائم للخادم ولا يتزامن بين الأجهزة.
- هذه نواة استدلال حتمية قابلة للفحص (بحث + سياق + قواعد)، وليست شبكة عصبية مدرّبة أو ادعاءً بفهم بشري. «خطوات التفكير» المعروضة هي خطوات التشغيل القابلة للتحقق، لا سلسلة أفكار داخلية مزعومة.

## كتب Google Drive ومكتبة Firestore الخاصة

صاحب المشروع أكّد صلاحية الفهرسة للاستخدام الداخلي واختار Firestore الخاص. جرى حصر المجلد المرتبط: **22 ملف PDF** مباشرة، تتضمن نسخًا متكررة/متقاربة ومواد ASME/AWS وCSWIP/CIP. لم تُنسخ ملفات الكتب أو نصوصها إلى Git أو `docs/` أو حزمة الموقع العامة.

أُضيفت بنية مزامنة خاصة، لكنها **لم تُشغّل بعد**؛ موصل Drive في هذه الجلسة لا يمنح Vercel صلاحية Google Drive أو Firestore، ولا أستطيع إنشاء/قراءة أسرار المالك أو مشاركة المجلد نيابة عنه. التفعيل يحتاج إعدادًا لمرة واحدة من مالك المشروع:

1. أنشئ Service Account بصلاحية Firestore، وامنحه وصول قراءة إلى Drive API ثم شارك مجلد «مدرسه» معه من Drive.
2. أضف ملف JSON كمتغير مشفّر `INSCO_PRIVATE_KNOWLEDGE_SERVICE_ACCOUNT` مباشرة في إعدادات Vercel (لا تلصقه في المحادثة أو Git). لا حاجة لنشر قواعد Firestore: الفهرس قابل للقراءة/الكتابة من الخادم فقط عبر Admin SDK؛ قواعد Firestore العادية تظل افتراضيًا مانعة للعميل.
3. من بيئة مالك موثوقة تشغّل `npm run knowledge:sync:drive -- --dry-run` لمراجعة القائمة، ثم `npm run knowledge:sync:drive` لفهرسة الصفحات والمقاطع إلى `agent_knowledge_chunks`. أعد التشغيل لتحديث النسخ؛ التحديث مرحلي/idempotent، والنسخة القديمة تظل فعالة حتى يكتمل الجديد. لا تُخزّن ملفات PDF نفسها في Firestore.
4. وصول الكتب مغلق افتراضيًا. بعد مراجعة المستخدم الداخلي المخوّل، يمنحه مالك الخدمة claim باسم `inscoKnowledgeAccess` عبر `npm run knowledge:grant-access -- <UID-or-email>` (والإلغاء بـ `--revoke`). العملاء غير المخوّلين لا يحصلون على مقتطفات الكتب؛ يظل لهم فهرس الموقع المنشور فقط. يتطلب المستخدم تسجيل الدخول وتجديد ID token.
5. الوكيل والمستشار ومساعد فحص المجتمع يرسلون ID token للخادم؛ الخادم يتحقق من claim قبل بحث Firestore. الاستشهادات الخاصة تعرض اسم الملف/الصفحة ورابط Drive، مع تنبيه أنها مادة غير مراجعة ولا تُعد قرارًا فنيًا معتمدًا. مدير الموقع لا يحتاج كتب الأكواد لتحليل التليمترية.

الاستيراد النصي يتجاوز الصفحات التي لا تحتوي نصًا قابلًا للاستخراج (مثل PDF المصوّر) ويذكرها كـ `empty`؛ OCR غير مفعّل، فلا تُخمن محتوياتها. لم يُفعّل روبوت كشط ويب عشوائي؛ المزامنة مقصودة لمجلد Drive الذي أقره المالك فقط.
