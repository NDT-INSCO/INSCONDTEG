# بوابة إدارة موقع إنسكو

في تذييل بوابة الشركة (`#company-footer`)، اضغط أيقونة المفتاح الذهبية بجوار اسم
الشركة. يوجد مفتاح أيضًا في تذييل الأكاديمية. تفتح الأيقونة صفحة دخول مستقلة
(`#admin`). بعد تسجيل الدخول بكلمة المرور أو بمفتاح مرور مسجّل، تظهر لوحة الإدارة
بالعربية أو الإنجليزية:

- **نظرة عامة:** عدد الطلبات حسب الحالة ونشاط الاستلام خلال سبعة أيام (UTC)، مع تنبيه
  للطلبات المفتوحة منذ 48 ساعة فأكثر. الأرقام من صندوق الطلبات وليست إحصاءات للزوّار.
- **صندوق الطلبات:** بحث باسم الشركة أو رقم الطلب، وتصفية حسب الحالة، وبيانات التواصل.
  يمكن نقل الطلب بين «جديد» و«قيد المتابعة» و«مغلق». تغيير الحالة داخلي ولا يرسل بريدًا للعميل.
- **إعلانات الموقع:** معاينة رسالة باللغتين، ثم حفظها كمسودة مخفية أو نشرها أعلى الصفحة
  الرئيسية للشركة. يراها الزوّار عند فتح الصفحة أو إعادة تحميلها.

## تشغيل محلي

1. استخدم Node **22.13** أو أحدث، ثم `npm ci`.
2. انسخ `.env.example` إلى `.env`. اضبط `ADMIN_PASSWORD` على كلمة مرور فريدة من
   8 إلى 128 حرفًا، والأفضل توليدها بمدير كلمات مرور. تُقبل الحروف والأرقام والرموز،
   وكلمة المرور حسّاسة لحالة الأحرف. اترك `ADMIN_ORIGIN` فارغًا للتشغيل المحلي.
3. نفّذ `npm run dev` وافتح `http://localhost:3000/#admin` أو اضغط المفتاح في التذييل.

لا تضع كلمة المرور في `src/` أو `docs/` أو في متغيّر يبدأ بـ `VITE_`. لا توجد كلمة
مرور افتراضية. عند غياب الإعداد تُعطّل البوابة بدل السماح بدخول شكلي. يمكن الاستمرار
باستخدام `ADMIN_PIN` الرقمي (8 إلى 32 رقمًا) إذا لم تُضبط `ADMIN_PASSWORD`.

تنتهي جلسة الدخول بعد 4 ساعات. يتوقف الخادم مؤقتًا عن قبول كلمة المرور بعد 5 محاولات
خاطئة من العنوان نفسه خلال نافذة مدتها 15 دقيقة، مع حد عام أيضًا. لإبدال كلمة المرور،
غيّر إعداد الخادم وأعد تشغيله؛ ستُبطَل الجلسات القديمة، لكن مفاتيح المرور لا تُلغى
تلقائيًا. تسجيل الخروج يبطل الجلسة الحالية.

## الدخول بالبصمة أو Face ID

1. افتح بوابة الإدارة في تبويب مستقل على عنوان HTTPS المعتمد. للاختبار المحلي،
   اضبط `ADMIN_ORIGIN=http://localhost:3000` وافتح نفس العنوان، لا `127.0.0.1`.
2. سجّل الدخول **بكلمة المرور**. افتح **مفاتيح المرور → إضافة مفتاح مرور**، واكتب
   اسمًا للجهاز إن أردت ثم أكمل التحقق الذي يطلبه النظام.
3. سجّل الخروج. على جهاز ومتصفح متوافقين، يظهر **الدخول بالبصمة أو Face ID** حين
   يكون هناك مفتاح مسجّل على هذا العنوان. قد يطلب الجهاز رمز قفل الشاشة بدل البصمة أو الوجه.
   يظل زر تسجيل الدخول بكلمة المرور متاحًا.

تتطلب الإضافة والإلغاء جلسة دخول بكلمة المرور خلال آخر 10 دقائق. يمكن تسجيل حتى
10 مفاتيح لهذا العنوان. لإلغاء مفتاح جهاز مفقود، ادخل بكلمة المرور واختر **إلغاء المفتاح**؛
لن يستطيع المفتاح الدخول مرة أخرى، وتُنهى جلساته المفتوحة. احذفه أيضًا من مدير مفاتيح
الجهاز إن أمكن. لا ترفع صورًا أو بصمات: تحقُّق الجهاز يتم محليًا، ولا يستلم الخادم
إلا إثبات WebAuthn والمفتاح العام اللازم للتحقق.

مفاتيح المرور مرتبطة بعنوان الإدارة المسجّل؛ إذا غيّرت `ADMIN_ORIGIN` أو انتقلت من
رابط المعاينة إلى نطاق الإنتاج، سجّل الدخول بكلمة المرور وأضف مفاتيح جديدة هناك.
تحديات التحقق أحادية الاستخدام وتنتهي بعد دقيقتين، ومحاولات مفتاح المرور لها حد مستقل
عن كلمة المرور. إعداد خادم ثابت وتخزين دائم يجعل المفاتيح تبقى بعد إعادة تشغيله.

## النشر المجاني: Netlify وTurso

يبقى الموقع العام على GitHub Pages. ننشر **بوابة الإدارة فقط** على Netlify، ونحفظ
الطلبات والإعلانات والجلسات ومفاتيح المرور في قاعدة **libSQL** مشتركة على Turso.
اختر **Free** في الحسابين؛ لا تحتاج إلى ترقية Vercel، ولا إلى شراء نطاق أو تفعيل
ميزة حماية الموقع بكلمة مرور من Netlify. كلمة المرور تتحقق منها البوابة نفسها.
خطتا [Netlify Free](https://www.netlify.com/solutions/web-applications/) و[Turso Free](https://turso.tech/pricing)
لهما حدود استخدام؛ [إذا نفد رصيد Netlify الشهري تتوقف البوابة مؤقتًا](https://docs.netlify.com/manage/accounts-and-billing/billing/resume-paused-projects/).

1. افتح [استيراد مشروع في Netlify](https://app.netlify.com/start) واختر **GitHub**، ثم
   استورد [`NDT-INSCO/INSCONDTEG`](https://github.com/NDT-INSCO/INSCONDTEG) بعد وصول
   هذا الإعداد إلى `main`. اختر `main` كفرع Production واترك مجلد المشروع على الجذر
   (ليس `docs/`). يحدد `netlify.toml` أمر `npm run build:hosted`، ومجلد `dist`،
   ودالة التشغيل في `netlify/functions`. تستخدم `.nvmrc` إصدار Node 22.
   اختر اسم مشروع ثابتًا قبل تسجيل مفاتيح المرور؛ رابط `*.netlify.app` يكفي.
2. من [لوحة Turso](https://app.turso.tech/) أنشئ قاعدة **libSQL** مخصصة للإدارة
   في منطقة واحدة. استخدم رابط القاعدة الأساسية ورمز قراءة وكتابة **لهذه القاعدة فقط**،
   وليس رمز حساب Turso. لو لم يظهر اختيار المحرك في اللوحة، استخدم
   [Turso CLI](https://docs.turso.tech/quickstart): `turso db create insco-admin`
   **بدون** `--tursodb`، ثم `turso db show insco-admin --url` و
   `turso db tokens create insco-admin` على جهازك. تُنشئ البوابة الجداول تلقائيًا.
3. في مشروع Netlify افتح [**Project configuration → Environment variables**](https://docs.netlify.com/build/environment-variables/get-started/#site-environment-variables).
   اختر القيم حسب سياق النشر، واضبطها لـ **Production** فقط. لا تُضف قيمًا إلى
   Deploy Previews أو Branch deploys. إذا توفّر تحديد النطاق، استخدم **Functions**؛
   نطاق All scopes الافتراضي يكفي في Free. استخدم الإعدادات التالية:

   | المتغير | الإعداد |
   | --- | --- |
   | `ADMIN_ORIGIN` | رابط HTTPS الثابت للمشروع، مثل `https://your-project.netlify.app`، بدون `/` نهائية أو `#admin` |
   | `ADMIN_PASSWORD` | كلمة مرور قوية وفريدة تختارها وتحفظها في مدير كلمات مرور |
   | `TURSO_DATABASE_URL` | رابط قاعدة libSQL، يبدأ بـ `libsql://` أو `https://` |
   | `TURSO_AUTH_TOKEN` | رمز القراءة والكتابة المخصص لقاعدة الإدارة |
   | `ADMIN_STATE_KEY` | مفتاح عشوائي من 32 بايت (64 خانة hex)، ثابت لكل نسخ الدالة |
   | `PUBLIC_SITE_ORIGIN` | `https://ndt-insco.github.io`، بدون `/INSCONDTEG/` |

   ولّد مفتاح الحالة على جهازك وانسخه إلى لوحة الاستضافة مباشرةً:

   ```bash
   node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'
   ```

   علّم كلمة المرور والرمز ومفتاح الحالة كأسرار إن ظهر الاختيار. لا تضعها في
   `netlify.toml` أو Git أو المحادثة أو في متغير يبدأ بـ `VITE_`.
   يمكن استخدام `ADMIN_DATABASE_URL` / `ADMIN_DATABASE_AUTH_TOKEN` بدل ثنائي Turso،
   وليس بالإضافة إليه. لا تضبط `ADMIN_DATA_DIR` أو `TRUST_PROXY` في الدالة.
4. من **Deploys** شغّل نشرًا جديدًا للـProduction بعد حفظ المتغيرات. استخدم رابط
   المشروع الثابت نفسه، لا رابط Deploy Preview أو رابط نسخة بعينها. افتح
   `/api/admin/dashboard` قبل الدخول: الرد الصحيح **`401`** وJSON
   `{"error":"signed_out"}`. افتح بعدها `/#admin` في تبويب مستقل، وجرّب الباسورد ثم
   سجّل مفتاح مرور على جهازك، واختبره بعد الخروج. لا تربط المفتاح الذهبي إلا بعد النجاح.
5. اربط الموقع العام باتباع خطوات GitHub Pages أدناه. بناء بوابة الإدارة يستخدم
   واجهة API على نفس النطاق. مستشار الأكاديمية (`/api/ai/*`) ليس جزءًا من هذه الدالة.

ظهور `503 not_configured` يعني غالبًا أن الإعدادات ناقصة أو أنك فتحت رابط معاينة،
أو لم تنشر من جديد. `403 origin_not_allowed` يعني أن العنوان أو مصدر الطلب لا يطابق
`ADMIN_ORIGIN`. في حالة `503 storage_error` راجع رابط libSQL وصلاحية رمز القاعدة
وخطة التخزين. لا تستخدم قرص الدالة لحفظ البيانات؛ القاعدة المستضافة لازمة.

لتدوير كلمة المرور في الاستضافة: غيّرها، ولّد `ADMIN_STATE_KEY` جديدًا، وأعد نشر
Production لإبطال الجلسات السابقة. ألغِ مفاتيح الأجهزة غير الموثوقة من لوحة الإدارة،
فهي لا تُلغى تلقائيًا. تغيير النطاق يتطلب تسجيل مفاتيح مرور من جديد. الطلبات القديمة
في ملف محلي لا تنتقل تلقائيًا.

## بديل: بوابة الإدارة على Vercel

ما زال `vercel.json` يدعم نفس الواجهة ونفس دالة الإدارة على Vercel. استخدمه فقط
بخطة مناسبة حسب [شروط الاستخدام التجاري لدى Vercel](https://vercel.com/docs/limits/fair-use-guidelines#commercial-usage)،
أو استخدم Netlify Free كما سبق. المشروع `inscondteg` منشور على
<https://inscondteg.vercel.app>؛ نجاح بناء المشروع لا يعني أن الإدارة مُفعّلة.
لا تستخدم عنوان نسخة Deployments المتغيّر أو رابط معاينة بوصفه عنوان الإدارة.

1. افتح **Settings → Environment Variables** في المشروع. عند استخدام النطاق
   الإنتاجي الحالي، اضبط `ADMIN_ORIGIN=https://inscondteg.vercel.app` في **Production**.
2. أضف `ADMIN_PASSWORD` و`ADMIN_STATE_KEY`، وثنائي `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN`
   لقاعدة libSQL كما في الجدول أعلاه. أو استخدم ثنائي `ADMIN_DATABASE_URL` و`ADMIN_DATABASE_AUTH_TOKEN`
   بدل ثنائي Turso، لا تخلط بينهما. ضع الأسرار مباشرةً في لوحة الاستضافة كـ **Sensitive**
   للإنتاج فقط، لا في المحادثة أو المستودع أو `VITE_*`. لا تضبط `ADMIN_DATA_DIR`.
3. بعد حفظ المتغيّرات كلها، اعمل **Redeploy** لآخر نشر إنتاجي. شغّل الفحص التالي
   من جهازك مع Node 22.13+ بعد `npm ci`، أو افتح `/api/admin/dashboard` على النطاق
   الإنتاجي في تبويب مستقل دون تسجيل الدخول وتحقق من الرد `401` و`{"error":"signed_out"}`.

   ```bash
   npm run admin:check -- https://inscondteg.vercel.app
   ```

   الفحص يرسل طلب `GET` واحدًا بلا كلمة مرور أو ملفات ارتباط ولا يتبع إعادة التوجيه.
   يميّز بين إعداد ناقص (`not_configured`)، وعنوان غير مطابق (`origin_not_allowed`)،
   وتعطّل التخزين (`storage_error`) أو استجابة غير متوقّعة. نجاح الفحص يؤكّد أن مسار
   الإدارة موجود ويتطلب جلسة؛ **لا** يؤكّد صحة كلمة المرور. بعده افتح
   <https://inscondteg.vercel.app/#admin> واختبر الدخول والخروج قبل ربط مفتاح التذييل.

## بديل: خادم Node مع قرص دائم

شغّل `server.ts` على **خادم Node واحد** خلف وسيط HTTPS. اترك منفذ Node داخليًا،
واضبط المتغيرات التالية كإعدادات للخادم فقط، لا كمتغيرات بناء عامة:

| المتغير | القيمة |
| --- | --- |
| `ADMIN_PASSWORD` | كلمة المرور التي يختارها صاحب الموقع ويحفظها كسرّ في إعدادات الخادم |
| `ADMIN_ORIGIN` | عنوان HTTPS باسم نطاق ثابت مثل `https://admin.example.com`، دون مسار أو `#admin`. يُستخدم اسم النطاق نفسه لـ WebAuthn. |
| `ADMIN_DATA_DIR` | مسار مجلد خاص على وحدة تخزين دائمة مثل `/var/lib/insco/admin` لحفظ الطلبات والنصوص ومفاتيح التحقق العامة |
| `TRUST_PROXY` | عناوين أو شبكات الوسطاء الموثوقين فقط؛ مثل `loopback` مع وسيط على الجهاز نفسه يضبط رؤوس إعادة التوجيه |
| `PUBLIC_SITE_ORIGIN` | يُترك فارغًا للاستضافة على نفس النطاق. لموقع Pages اضبطه على `https://ndt-insco.github.io` دون مسار المستودع |

```bash
npm ci
npm run build:hosted
NODE_ENV=production npm start
```

يبقى الدخول على نفس نطاق الخادم الذي يقدّم صفحة الإدارة. تعتمد حماية الجلسة على
`HttpOnly` و`SameSite=Strict` و`Secure` على HTTPS؛ افتح الصفحة في تبويب مستقل إذا
كان المتصفح يمنع الكوكيز داخل المعاينات المضمّنة. تُحفَظ الطلبات والنصوص ومفاتيح
التحقق العامة في ملف SQLite (`admin.sqlite`) في المجلد الخاص؛ احتفظ بنسخة احتياطية
محمية من قاعدة البيانات ولا تضعها أو ملفاتها المرافقة في `public/` أو `docs/` أو
`dist/`. تخزين الجلسات والتحديات وحدود الدخول يستخدم القاعدة نفسها؛ مع ملف محلي
تعمل البوابة على خادم واحد، وتُبطَل جلسات الدخول عند إعادة تشغيله. راجع سياسة الاحتفاظ
ببيانات العملاء قبل استخدام الصندوق على الموقع العام.

## إذا بقي الموقع على GitHub Pages

GitHub Pages ينشر ملفات ثابتة ولا يتحقق من كلمة المرور. في الموقع الرسمي تحت
<https://ndt-insco.github.io/INSCONDTEG/> يفتح مفتاح التذييل بوابة الإدارة المعتمدة
على <https://inscondteg.vercel.app/#admin> في تبويب مستقل، ورابط `#admin` القديم
يعرض زر فتح البوابة. لا يُعرض حقل كلمة مرور على Pages ولا يرسل المفتاح طلبات API.
الرابط المدمج يخص هذا المسار الرسمي فقط؛ لا يحتاج إلى متغيّر إضافي في Actions،
ولا يفعّل إعلانات الموقع أو يغيّر جهة عروض الأسعار. فحص **Admin link readiness**
في GitHub Actions يشغّل `npm run admin:check -- --pages-default` على العنوان المدمج
بدون بيانات دخول. هذا الفحص لا يغني عن تجربة الدخول والخروج يدويًا.

لاستخدام عنوان آخر أو ربط نسخة Pages مختلفة:

1. شغّل `npm run admin:check -- https://admin.example.com` بالعنوان الفعلي، ثم اختبر
   الدخول والخروج يدويًا من البوابة. لو فشل الفحص أو الدخول، اترك رابط الإدارة في
   الموقع العام دون تغيير. `PUBLIC_SITE_ORIGIN` اختياري للإعلانات وطلبات الأسعار؛
   لا يحتاجه رابط الإدارة ولا يسمح للموقع العام باستدعاء مسارات الإدارة عبر النطاقات.
2. في **بناء الموقع العام فقط**، اضبط `VITE_ADMIN_PORTAL_URL` لتجاوز العنوان المدمج
   أو لتعيين عنوان للنسخة الأخرى. استخدم رابط HTTPS مستقل يعمل عليه الخادم، لا رابط
   Pages أو عنوان الموقع نفسه. لتعطيل الرابط مؤقتًا اضبط القيمة على `off` وأعد البناء والنشر.
3. ليصل النموذج العام إلى صندوق الإدارة، وجّه `VITE_RFQ_ENDPOINT` إلى الخادم نفسه
   مثل `https://admin.example.com`. الطلبات المرسلة مباشرة إلى Google Apps Script
   أو جهات أخرى لا تظهر في هذا الصندوق، والطلبات القديمة لا تُستورد تلقائيًا.
4. مع مصدر Pages الحالي (`main` / `docs`)، أعد `npm run build && npm run site:check`
   بنفس متغيّرات البناء العامة وضمّ `docs/` المولّد إلى التغيير. إذا كان المصدر GitHub
   Actions، اضبط المتغيّرين العامّين في **Actions → Variables** قبل إعادة النشر.
   يستخدم فحص `verify` المتغيّرات العامة نفسها لمقارنة بناء الصفحات بـ`docs/`.

على الخادم نفسه اترك `VITE_ADMIN_PORTAL_URL` و`VITE_RFQ_ENDPOINT` فارغين أثناء بناء
`dist/` ليستخدم مساراته الداخلية. بوابة الطلبات تخزّن الطلبات التي تقبلها على هذا
الخادم. إذا أُعد بريد أو webhook، يبقى قناة التسليم الأساسية وتُنسخ طلباته الناجحة
إلى الصندوق؛ بدونه يكون الصندوق نفسه قناة التسليم ولا يدّعي النموذج أنه أرسل بريدًا.
اطّلع على [إعداد عروض الأسعار](RFQ_AR.md) لتهيئة إشعارات الطلبات.

## التحقق

لو قَبِل الخادم بيانات الدخول لكن تعذّر تحميل اللوحة مؤقتًا، اضغط «إعادة التحقق من
الجلسة». يفحص الزر الجلسة الحالية دون إرسال كلمة المرور أو طلب التحقق من الجهاز مجددًا.
إذا لم يتعرّف الخادم على الجلسة، افتح العنوان المعتمد في تبويب مستقل وتأكد من السماح
بملفات تعريف الارتباط. يظل الخادم مسؤولًا عن صلاحية الجلسة وانتهائها.

`npm run test:admin` يفحص تشغيلاً فعليًا لتسجيل مفتاح مرور تجريبي، التحقق من توقيعه
وعنوانه وتحديه، منع إعادة استعمال التحدي، الإلغاء وانتهاء الجلسات. يختبر أيضًا مسار
كلمة المرور، تخزين طلبات الأسعار وإعلانات الموقع، ومسار المفتاح من التذييل. ويختبر دالتي
Netlify وVercel أمام قاعدة libSQL تجريبية للتحقق من مشاركة الجلسات وحفظ ملفات
الارتباط ومنع إعادة استخدام تحديات الدخول. يظل اختبار عنوان الإنتاج الفعلي بعد النشر خطوة منفصلة.
