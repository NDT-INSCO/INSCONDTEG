# تشغيل إدارة إنسكو داخل GitHub Pages

الهدف هو أن يبقى تسجيل الدخول وجميع أقسام الإدارة على [عنوان الموقع نفسه](https://ndt-insco.github.io/INSCONDTEG/#admin): النظرة العامة، الطلبات وتحديث حالتها، الإعلانات، مصنع البرمجيات ومفاتيح المرور. لا يستخدم هذا الوضع تسجيل الدخول بحساب GitHub، ولا ينقل المتصفح إلى Vercel أو Netlify. GitHub Pages يستضيف الواجهة؛ Netlify Functions تتحقق من الدخول وتقرأ وتحدّث قاعدة **libSQL/Turso الحالية**.

هذا الوضع **لا يتفعّل تلقائيًا**. طالما لم يُضبط عنوان API الإنتاج، يظل رابط الإدارة الحالي متاحًا. لا تضبط عنوانًا تجريبيًا أو عنوانًا لا تملكه في بناء Pages.

## ١. جهّز خادم الإدارة

1. بعد نشر الكود الذي يدعم هذا الوضع، اربط مشروعًا مملوكًا لك على [Netlify](https://app.netlify.com/start) بالمستودع `NDT-INSCO/INSCONDTEG`. استخدم `main` لفرع Production والعنوان الثابت للمشروع. يحدد `netlify.toml` جذر المشروع، بناء `dist/` والدالة `insco`. إصدار Node المحدد للمشروع هو 24.
2. من **Project configuration → Environment variables** اضبط المتغيرات في **Production**، وفي نطاق **Functions** إن كان متاحًا. لا تستخدم قيم الإنتاج في معاينات الفروع.

   | المتغيّر | القيمة |
   | --- | --- |
   | `ADMIN_PAGES_ENABLED` | `true`. يفعّل `/api/admin/pages/*` ويعطّل تسجيل الدخول التقليدي على **مشروع Netlify هذا فقط**. |
   | `ADMIN_ORIGIN` | عنوان Netlify الثابت `https://your-project.netlify.app` بدون مسار. **ليس** `ndt-insco.github.io`. |
   | `ADMIN_PASSWORD` | كلمة مرور قوية وفريدة، محفوظة في مدير كلمات مرور. لا يدعم هذا الوضع `ADMIN_PIN`. |
   | `ADMIN_STATE_KEY` | 32 بايت عشوائية بصيغة 64 خانة hex، ثابتة لكل نسخ هذه الدالة. استخدم مفتاحًا مستقلًا عن الخادم القديم. |
   | `TURSO_DATABASE_URL` | رابط **نفس قاعدة بيانات الإدارة الحالية**، لا قاعدة فارغة جديدة. |
   | `TURSO_AUTH_TOKEN` | رمز قراءة وكتابة مخصص لهذه القاعدة. يُفضَّل رمز مستقل لخادم Netlify. يمكن بدل الزوج استخدام `ADMIN_DATABASE_URL` و`ADMIN_DATABASE_AUTH_TOKEN`. |
   | `GEMINI_API_KEY` | مطلوب إذا أردت زر المسودة بالذكاء في المصنع. يبقى على الخادم. القوالب والمحاكاة تعمل بدونه. |

   أنشئ `ADMIN_STATE_KEY` على جهازك بـ `node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'`. أدخل الأسرار في لوحات المزودين فقط؛ لا تضعها في المحادثة أو Git أو `netlify.toml` أو أي متغيّر `VITE_*`. خذ نسخة احتياطية من قاعدة البيانات الحالية قبل تشغيل الخادم الثاني. جداول الطلبات والإعلانات مشتركة، ولا يحتاج هذا الوضع إلى استيرادها أو حذفها.
3. أعد نشر Production بعد حفظ المتغيّرات. الدالة ترفض المعاينات والإصدارات غير المنشورة وعناوين النشر البديلة. افحص العنوان الثابت **قبل تعديل بناء Pages**:

   ```bash
   npm run admin:check -- --pages-api https://your-project.netlify.app
   ```

   يتأكد الفحص من `401 signed_out` للوحة والمصنع، ومن `OPTIONS` للمتصفح ورفض المصادر الأخرى، بلا كلمة مرور أو تحديث بيانات أو استدعاء Gemini. `404` تعني أن المسار أو تفعيل Pages غير موجود؛ `503 not_configured` تعني إعدادًا ناقصًا أو نسخة غير منشورة. الفحص لا يثبت صلاحية كلمة المرور أو أن القاعدة هي القاعدة المقصودة. اختبر سير العمل قبل التحويل في بيئة معزولة ببيانات تجريبية؛ `npm run test:admin` يفحص الدالة ضد قاعدة libSQL تجريبية مستقلة.

## ٢. حوّل مدخل الإدارة بعد التحقق

- **المصدر الحالي `main:/docs`:** ضع **عنوان API العام فقط** في `INSCO_PAGES_ADMIN_API_URL` داخل `src/admin/pages.ts`. اترك `VITE_ADMIN_PORTAL_URL` غير مضبوط. ابْنِ النسخة بـ `SITE_BASE=/INSCONDTEG/ npm run build`، وشغّل `npm run site:check`، وضمّ `docs/` المولّد إلى نفس التغيير. لا تغيّر إعداد مصدر Pages أو إعداد RFQ أو المستشار العام من أجل هذه الخطوة.
- **لو تغيّر مصدر النشر إلى GitHub Actions لاحقًا:** `VITE_PAGES_ADMIN_API_URL` هو متغيّر بناء عام ويمكن ضبطه في **Actions → Variables**. لهذا المتغيّر أولوية على عنوان API المدمج. اترك `VITE_ADMIN_PORTAL_URL` غير مضبوط في بناء التحويل؛ أي قيمة صريحة فيه تتجاوز وضع Pages. حافظ على تطابق متغيّرات `verify` مع بناء `docs/` الملتزم به.
- بعد نشر التحويل، افتح [بوابة الإدارة](https://ndt-insco.github.io/INSCONDTEG/#admin) في تبويب مستقل. تحقّق من الدخول والخروج، وأن الطلبات والإعلان الحالي ظاهرَان كما هما. لا تغيّر إعلانًا عامًا أو بيانات عميل لمجرد الاختبار. تحقّق من المصنع بقالب محلي؛ تجربة Gemini الفعلية تحتاج موافقة لأنها قد تُحتسب من الرصيد. تأكد أن رابط المفتاح في التذييل يبقى على Pages. لو فشل التحقق، أعد البناء بعنوان API فارغ (أو اضبط `VITE_PAGES_ADMIN_API_URL=off` وأعد البناء)، وانشر `docs/` للعودة إلى الرابط القديم. لا تحذف المشروع القديم أو تدوّر أسراره خلال التحويل.

## الجلسة ومفاتيح المرور

- الطلبات الخاصة ترسل رمز جلسة عشوائيًا عبر `Authorization` فقط، بلا ملفات ارتباط بين الموقعين. يحتفظ التبويب بالرمز في ذاكرته لمدة تصل إلى 30 دقيقة، وتتحقق الدالة من كل طلب. تحديث الصفحة أو مغادرة البوابة يفقد الجلسة محليًا، وزر الخروج يلغيها على الخادم عندما يكون متاحًا. لا يُحفظ الرمز أو كلمة المرور في رابط أو `localStorage` أو `sessionStorage`. تُحفظ بصمة الرمز، وليس الرمز نفسه، في القاعدة.
- CORS يقبل `https://ndt-insco.github.io` فقط. المسار `/INSCONDTEG/` هو قيد في الواجهة، **وليس** حدّ ثقة في المتصفح: مشروعات Pages الأخرى على نفس النطاق تشترك معه في الأصل. احصر صلاحيات النشر على هذا النطاق في جهات موثوقة، ولا تستخدم عنوانًا خاضعًا لجهة أخرى. CORS لا يغني عن كلمة المرور أو التحقق من الجلسة.
- مفاتيح المرور مرتبطة بـ `ndt-insco.github.io`. لا تعمل مفاتيح Vercel أو Netlify القديمة على Pages. ادخل أول مرة بكلمة المرور ثم أضف مفتاحًا من **مفاتيح المرور** خلال أول عشر دقائق. لا تلغِ المفاتيح القديمة قبل تأكيد البديل.
- يحافظ هذا التغيير على قنوات الاستقبال الحالية. الإعلانات المنشورة يقرأها موقع Pages من المسار العام `/api/site/announcement` بدون جلسة. الطلبات التي تصل إلى نفس قاعدة البيانات تظهر في صندوق الإدارة؛ لا يجمع هذا التحويل طلبات من مصادر أخرى ولا يغيّر `VITE_RFQ_ENDPOINT` أو إعدادات Manus/المستشار العام.
