# سياسة INSCO AI: العقل المحلي أولاً والنموذج الخارجي اختيارياً

## القرار المعماري

تعتمد المنصة سياسة **Local-First, External-Optional**:

1. العقل المحلي هو مسار التشغيل الأساسي، ولا يحتاج إلى مفتاح API خارجي.
2. يسمح باستدعاء نموذج خارجي فقط عندما تكون المهمة مناسبة لذلك، ويكون المزود مهيأً، وتسمح سياسة الخصوصية ونوع البيانات بذلك.
3. فشل المزود الخارجي أو انتهاء الحصة أو انتهاء المهلة لا يحول الطلب إلى خطأ نهائي؛ يجب الرجوع إلى أفضل نتيجة محلية آمنة متاحة.
4. لا يُرسل محتوى بوابة الإدارة أو العملاء أو الملفات الخاصة/المرخصة إلى مزود خارجي افتراضياً.
5. لا يجوز اختلاق مواصفات NDT أو حدود قبول أو مراجع. عند نقص الدليل، يصرّح المساعد بذلك ويطلب المصدر أو يرفض الاستنتاج الفني.
6. يجب إظهار مصدر الإجابة بوضوح: محلي، خارجي، أو محلي مع تحسين خارجي، مع فصل المراجع المسترجعة عن ادعاءات النموذج.

## سلوك التوجيه المطلوب

### أوضاع التشغيل

- `local`: محلي فقط؛ يمنع كل الاتصالات بمزودي النماذج.
- `auto`: محلي أولاً؛ يمكن التصعيد إلى مزود خارجي عند الحاجة وبعد اجتياز سياسة الخصوصية. عند فشل المزود، استجابة محلية آمنة أو اعتذار واضح.
- `gemini` و`manus`: أوضاع تشغيل صريحة للمشغل، لا ينبغي أن تجعل الخدمات الخارجية شرطاً لتشغيل الموقع أو أدوات المعرفة المحلية.

يجب توحيد تفسير الأوضاع في دالة مركزية بدلاً من تكرار فحوصات متباينة مثل `AI_PROVIDER === 'local'` في كل مسار. يجب ألا يُعامل `auto` كمرادف لـ«خارجي فقط».

## مسارات المنتج التي يجب توحيدها

- Tutor والبث النصي SSE.
- User Copilot.
- Community Assist.
- Site Manager.
- استرجاع مكتبة الأكاديمية ومصادر المعرفة الخاصة.
- أدوات الملفات والصور والمحاكيات والحسابات الهندسية.

كل مسار يحتاج سياسة موحدة لتحديد المحرك، وفحص صلاحية البيانات للإرسال، والمهلة، وإعادة المحاولة، والرجوع المحلي، وتسجيل المصدر.

## قواعد الخصوصية

- لا تُرسل كلمات المرور أو مفاتيح API أو رموز الجلسات أو بيانات العملاء أو محتويات المستندات الخاصة إلى أي مزود خارجي.
- المصادر الخاصة أو المرخصة تُستخدم محلياً فقط ما لم توجد موافقة صريحة وسياسة تعاقدية تسمح بخلاف ذلك.
- اجعل الإرسال الخارجي معطلاً افتراضياً للبيانات الحساسة، ولا تعتبر مجرد تفعيل `auto` موافقة على مشاركة الملفات.
- لا تسجل نصوص المحادثات أو الأسرار في سجلات التشغيل؛ سجّل فئة المحرك وسبب الانتقال ورمز الفشل فقط.

## خطة التنفيذ

### المرحلة 1 — التوجيه والرجوع الآمن
- إنشاء سياسة/واجهة مركزية لاختيار المحرك.
- جعل `auto` محلياً أولاً بالفعل في جميع مسارات الوكلاء، لا في Tutor فقط.
- عند عدم كفاية الاسترجاع المحلي، يمكن التصعيد الخارجي فقط للمدخلات المسموح بها.
- عند timeout أو 429 أو 5xx أو غياب المفتاح، ارجع إلى إجابة محلية مؤهلة أو رسالة صريحة؛ لا تُسقط الطلب ولا تدّعِ أن إجابة محلية مولّدة هي جواب موثوق.
- توحيد بيانات الحالة والـ telemetry بحيث يظهر المحرك الفعلي لكل طلب.

### المرحلة 2 — ذاكرة المحادثة
- ذاكرة جلسة واضحة النطاق، مع فصل سياق المستخدم عن بيانات الشركة.
- حدود حجم ومدة احتفاظ قابلة للضبط.
- إمكانية بدء محادثة جديدة ومسح سياق الجلسة.
- عدم تمرير الذاكرة الخاصة إلى مزود خارجي تلقائياً.

### المرحلة 3 — الملفات والصور
- استخراج نص PDF وDOCX والجداول مع حفظ أرقام الصفحات ومصدر كل مقتطف.
- OCR وتحليل الصور كقدرات مستقلة يمكن تشغيلها محلياً.
- فحص نوع الملف وحجمه ومحتواه قبل المعالجة.
- عند غياب نموذج رؤية محلي، يوضح النظام القيد ولا يرسل الصورة خارجياً دون سماح واضح.

### المرحلة 4 — الاستدلال والأدوات
- آلة حاسبة ووحدات وتحويلات وهندسة موثوقة قابلة للاختبار.
- أدوات NDT محددة بعقود إدخال/إخراج واضحة.
- فصل الحسابات الحتمية عن النص التوليدي.
- كل نتيجة فنية مرتبطة بمرجع أو موسومة بأنها حساب/استنتاج مع افتراضاته.

### المرحلة 5 — تكامل الأكاديمية والمحاكيات
- ربط المساعد بأدوات المحاكاة عبر واجهات آمنة موثقة.
- لا يدّعي التحكم بمحاكاة إلا إذا نفّذ الأداة وتلقى نتيجة فعلية.
- إعادة نتائج المحاكاة المنظمة إلى سياق المحادثة.

### المرحلة 6 — التحقق والإطلاق
- اختبارات دون مفاتيح خارجية ودون اتصال خارجي.
- اختبارات فشل المزود والمهلة والحصة ورفض المفتاح.
- اختبارات منع تسريب بيانات العملاء والإدارة والمستندات الخاصة.
- اختبارات عربية/إنجليزية، الاستشهادات، وSSE.
- بناء المشروع وفحوص الأنواع والاختبارات قبل الدمج والنشر.

## معايير القبول

1. `local` لا يصدر أي طلب شبكة إلى مزود AI خارجي.
2. `auto` يحاول المحلي أولاً، ولا يتصل بالخارج إلا عند تحقق شروط التصعيد.
3. إذا كان المزود الخارجي غير مهيأ أو متعطلاً، تظل وظائف المعرفة المحلية متاحة.
4. لا تُرسل بيانات حساسة أو ملفات خاصة إلى الخارج.
5. كل إجابة تعرض المحرك الفعلي ومصدر الاستشهادات بدقة.
6. لا تُختلق مواصفة أو قيمة قبول أو مرجع عند غياب المصدر.
7. يمر build واختبار الأنواع والاختبارات ذات الصلة، مع اختبارات انقطاع الخدمة.

## ملاحظة عن الوضع الحالي

المستودع يحتوي بالفعل على `BRAIN_MODEL` و`resolveAiProvider` ووضع افتراضي `local` ومسار `/api/ai/selftest`. كما أن `server/ai/gateway.ts` يستخدم `LOCAL_ONLY = AI_PROVIDER === 'local'` في عدة فروع، بينما وصف `auto` في تعليق `src/ai/brain/index.ts` يقول إنه محلي أولاً. لذلك يجب التحقق من السلوك الفعلي لكل مسار؛ وجود التعليق أو اختبار self-test وحده لا يثبت أن كل الوكلاء يطبقون الرجوع المحلي. هذه الوثيقة تحدد السلوك المستهدف ولا تدّعي أن المراحل البرمجية قد نُفذت أو اختُبرت.
