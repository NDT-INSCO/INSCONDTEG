# Google AI Studio / Gemini API — ما طُبِّق وما لم يُطبَّق

آخر تحديث: أكتوبر 2026.
هذا الملف يشرح كيف صار "مستشار NDT الذكي" في أكاديمية إنسكو مبنياً على
واجهات Google الحالية، وما الذي رُفض تطبيقه وسببه، وكيف يُشغَّل ويُختبر.
المرجع التنفيذي هو الكود نفسه: `src/ai/*` و`server.ts`.

---

## 1. الخلاصة في ثلاثة أسطر

- الموقع يُنشر ملفات ثابتة على GitHub Pages، والمفتاح لا يجوز أن يكون فيه.
  لذلك أُضيفت **بوابة خادم** صغيرة (`server.ts`) تحمل المفتاح وتتحدث مع Gemini.
- الطلب يمر عبر بحث حقيقي في مكتبة إنسكو (132 وثيقة) قبل النموذج، وكل إجابة
  تحمل **استشهادات** بصفحات حقيقية. بلا مطابقة ⇒ رفض صريح، لا تخمين.
- الواجهة الحالية تُسمّى **Interactions API** وهي المسار الأول؛ واجهة
  `models.generateContent*` القديمة بقيت كاحتياط فقط.

| **Managed Agents / background=True** | ❌ غير مطلوبة | لا يوجد وكيل طويل التشغيل في هذا النطاق |
| **Flex / Priority tiers** | ⏸️ عند النشر | `service_tier` يُضبط في الخادم إذا احتجنا تسعيراً أرخص لحركة غير عاجلة |

## 3. المعمارية

```
المتصفح (GitHub Pages, ثابت)
  ├── src/ai/search.ts  ← بحث BM25 داخل المتصفح (يعمل بلا خادم)
  ├── src/ai/corpus.ts  ← 132 وثيقة من نفس بيانات الكتب والمقررات
  └── src/ai/client.ts  ← fetchTutorStatus / streamTutor
            │  POST /api/ai/tutor   (SSE)
            ▼
server.ts  (Express + @google/genai)
  ├── تحقق من الطلب            → 400 invalid_request
  ├── حد المعدل والسقف اليومي    → 429 rate_limited / budget_exhausted
  ├── هل يوجد مفتاح؟            → 503 not_configured (لا نص مزيّف)
  ├── استرجاع المقاطع + عتبة 4.2  → لا مطابقة = رفض صريح
  └── streamTutorText()
        ├── interactions.create({ stream: true })   ← المسار الأول
        └── models.generateContentStream(...)       ← احتياط (TUTOR_API_MODE)
            │
            ▼
        Gemini (3.8 Flash → 3.6 Flash → 2.5 Flash)
```

نقاط التصميم المهمة:

1. **لا مفتاح في المتصفح.** `src/ai/client.ts` يستدعي `gatewayBase()` التي تقرأ
   `VITE_AI_BASE_URL`، وإن كانت فارغة فالمسار نسبي `/api/ai/*`.
   على GitHub Pages لا يوجد خادم ⇒ الحالة `unreachable` وتقول الواجهة ذلك.
2. **حقيقة واحدة للأرقام.** عدد الصفحات والدروس يُشتق من `getCorpusStats()`
   (90 صفحة و35 درساً و7 مقررات = 132 وثيقة)، والرسالة التي كانت تقول
   "157 صفحة" ثابتة يدوياً صُحِّحت.
3. **العقد واحد.** `src/ai/contract.ts` يحدد النماذج والحدود والمسارات وأحداث
   SSE وأكواد الخطأ. الخادم والمتصفح والاختبارات تقرأ منه، فلا يتفرّق الاتفاق.
4. **`src/ai/transport.ts` معزول.** يستقبل عميلاً بنيوياً بسيطاً، لذا يُختبر
   بمزيف بلا شبكة، ولا يدخل في حزمة المتصفح.

## 4. آلية تنفيذ المسار الأول (Interactions API)

```ts
const stream = await ai.interactions.create(
  {
    model: 'gemini-3.8-flash',
    input: prompt,                 // المقاطع المسترجعة + السؤال
    system_instruction: system,
    generation_config: { temperature: 0.35, max_output_tokens: 1600 },
    stream: true,
    store: false,                  // لا نحفظ سؤال المتدرب
  },
  { signal }                       // إلغاء حقيقي عند إغلاق الصفحة أو المهلة
);

for await (const event of stream) {
  if (event.event_type === 'step.delta' && event.delta?.type === 'text') {
    yield event.delta.text;
  } else if (event.event_type === 'error') {
    throw new Error(event.error?.message ?? 'interaction stream reported an error');
  }
}
```

قواعد ثابتة في `streamTutorText`:

- **تسلسل النماذج** يعمل داخل النقل الواحد: نموذج غير موجود (404) ⇒ التالي.
- **لا تبديل صامت للنقل:** لو فشل الطلب بسبب الشبكة أو السلامة، يُبلَّغ الخطأ.
  الاحتياط القديم يعمل فقط إذا كانت الواجهة نفسها غير متاحة لهذا المشروع
  (`404/405/501/not implemented`)، ويُسجَّل سبب التبديل في سجل الخادم.
- **لا تكرار للنص:** إذا بدأ النموذج بالبث ثم فشل، لا يُعاد بالسؤال إلى نموذج
  آخر، وإلا قرأ المتدرب البداية مرتين.
- **الإلغاء صامت:** `AbortSignal` يوقف كل شيء دون رسالة خطأ للمستخدم.

التبديل يدوياً بمتغير واحد:

```bash
TUTOR_API_MODE=interactions   # الواجهة الحديثة فقط (يفشل بوضوح)
TUTOR_API_MODE=auto           # الافتراضي: حديث ثم قديم عند الحاجة
TUTOR_API_MODE=legacy         # القديم فقط (مفتاح/project قديم)
```

## 5. الاسترجاع والاستشهادات

`retrieveForTutor(question, { limit: 5 })` يبحث في:

- 90 صفحة كتاب + 7 نظرات عامة للمقررات + 35 درساً = 132 وثيقة.
- تطبيع عربي (همزات، تشكيل، أرقام) + جذوع + مرادفات ثنائية اللغة
  (`src/ai/synonyms.ts`) + BM25 مع وزن عنوان ×2.4.
- عتبة `minScore = 4.2`. أقل من ذلك ⇒ `confident: false`.

عند `confident: false` يحدث الآتي:

1. يُرسَل حدث `meta` بعدد استشهادات = 0.
2. تُكتب رسالة صريحة (بالعدد الحقيقي: 90 صفحة و35 درساً) تقول إن المكتبة لم
   تجد مطابقة وتقترح صياغة أخرى أو البحث اليدوي.
3. **لا يُستدعى النموذج أصلاً**، فلا يمكنه اختراع مصدر.

كل معرف استشهاد هو معرف حقيقي (`book-vt#p1`، `nde-ut#ut-calibration`)، والواجهة
تحوّله إلى قفزة مباشرة: الكتاب إلى صفحته داخل `EdbFlipbook`، والدرس إلى مقرره.
هذا ما يجعل `#edb` و`initialPage` جزءاً من العقد مع البحث.

**على Vercel (النطاق `inscondteg.vercel.app`):** البوابة صارت دالة واحدة
`api/ai.ts` تُقدّم `/api/ai/*` على نفس النطاق — لا خادم ثانٍ ولا `VITE_AI_BASE_URL`.

| البند | القيمة |
| --- | --- |
| الدالة | `api/ai.ts` (تعيد تركيب نفس الراوتر الذي يستخدمه `server.ts`) |
| إعادة التوجيه | `/api/ai/:path*` → `/api/ai` في `vercel.json` |
| المفتاح | `GEMINI_API_KEY` في Vercel → Environment Variables (Production + Preview) |
| المدة القصوى | `maxDuration: 60` ثانية |

> **سبب إضافة هذه الدالة:** قبلها كان النشر يخدم الموقع والإدارة و`/api/rfq` فقط،
> فأي نداء إلى `/api/ai/*` كان يعيد 404 من Vercel، والواجهة تُظهره كأنه
> «`GEMINI_API_KEY` غير مضبوط» — تشخيص خاطئ لمشكلة مسار مفقود. الآن النداء بلا مفتاح
> يعيد `503 not_configured` بصراحة، والمفتاح يعمل بمجرد إضافته وإعادة النشر.

**بعد أي تغيير في متغيرات Vercel يلزم Redeploy** — المتغيّرات لا تصل إلى نشر قائم.

### تشخيص جاهز: `/api/ai/status`

هذا المسار يجيب دائماً — حتى لو كان كل شيء آخر معطّلاً — ويقول الحقيقة:

```json
{"configured":false,"reason":"no_key","model":"…","retrieval":{"documents":0,"ready":false}}
```

- `reason: "no_key"` → المفتاح غير موجود في هذا النشر.
- `reason: "client_init_failed"` → المفتاح موجود لكن تهيئة العميل فشلت (مفتاح غير صالح أو مشروع محجوب).
- `retrieval.ready: false` → المكتبة المراجَعة لم تُقرأ (الحزمة أو مسار `edb`)، والمدرّس يجيب بلا استشهادات.
- **404 من هذا المسار** → الدالة غير منشورة على هذا النطاق، والمشكلة ليست في المفتاح أبداً.
- **500** → خطأ في الدالة نفسها؛ لم يعد يُخفى: كل خطأ يُعاد كـ JSON، والمهلة تُعاد `504` صريحة.

### المكتبة البديلة: الأكاديمية، بوسم صريح

سجل المراجعة في هذا المستودع لا يحتوي أي كورس موقَّع (`reviewedTutorDocuments` يُرجع صفراً)،
وكان المدرّس يمتنع عن كل سؤال — وهو سلوك صحيح لكنه يُقرأ كأن الذكاء الاصطناعي معطّل.

الآن للمدرّس ثلاث حالات فقط، ولا رابعة:

| الحالة | المصدر | ما يراه القارئ |
| --- | --- | --- |
| كورس مُراجَع موجود | `reviewed` | «المقاطع المسترجعة من المصادر المراجَعة» |
| لا يوجد مُراجَع، والمكتبة مليئة | `academy` | «مقاطع من مادة الأكاديمية — **غير مُراجَعة**» بلون تحذيري |
| لا شيء إطلاقاً | `none` | امتناع صريح، بلا توليد ولا تخمين |

- كل استشهاد يحمل `reviewed: false` في حالة الأكاديمية، ويظهر على الشريحة نفسها
  «غير مُراجَع · ص٨».
- **النموذج نفسه يُبلَّغ** أن المقاطع غير مُراجَعة، وأن الإجابة استرشادية للتعلّم لا مرجع معتمد.
- `retrieval.source` و`retrieval.reviewed` في `/api/ai/status` يقولان أي مكتبة تُجيب،
  فلا حاجة لتخمين.
- إيقاف البديل ممكن بـ`TUTOR_ALLOW_ACADEMY_FALLBACK=false` (يُستخدم في اختبارات الامتناع).
- النصوص كلها في دالة واحدة `src/ai/citationCopy.ts`، ويحرسها `tests/citationCopy.test.ts`،
  حتى لا يعود عنوان «المصادر المراجَعة» إلى إجابة غير مُراجَعة.

### سبب ٥٠٠ حقيقي حدث فعلاً: امتدادات الاستيراد

`FUNCTION_INVOCATION_FAILED` على كل مسار هو علامة على أن **تحميل الوحدة** فشل، لا على خطأ
في منطق المسار. السبب هنا: ملفات بوابة الذكاء الاصطناعي كانت تستورد بلا امتداد
(`from '../tutor/reviewedLibrary'`). `tsx` يحلّ ذلك، وNode ESM في Vercel لا يحلّه:
`ERR_MODULE_NOT_FOUND` قبل تنفيذ أي سطر.

القاعدة الآن، ويحرسها اختبار: **كل استيراد نسبي في سلسلة `api/*` يذكر امتداده `.js`**،
و`import type` وحده مستثنى لأنه يُحذف قبل التشغيل. الاختبار
`tests/vercelEsmImports.test.ts` يمشي على السلسلة من `api/ai.ts` و`api/insco.ts`
ويفشل إن نسي أحدهم الامتداد.

وطرق التحقق التي استُخدمت فعلاً بدل التخمين:

```bash

npx tsc api/ai.ts --ignoreConfig --outDir .vercel-sim --rootDir . \
  --module nodenext --moduleResolution nodenext --target es2022 \
  --esModuleInterop --skipLibCheck
node -e "import('./.vercel-sim/api/ai.js').then(m=>console.log(typeof m.default))"

# 2) هل النطاق المنشور يجيب؟ (تعليقات التشغيل تُقرأ من الـ API)

```

وفحص آلي بعد كل دفع إلى `main`: `.github/workflows/ai-probe.yml` يستدعي المسار ويطبع الكود
والجسم، ويفشل إن لم يكن `200` — بدل أن نصدّق أن النشر تم.»

### السبب الحقيقي الثاني: SDK بلا `interactions`

كل سؤال حر كان يرجع `502 upstream_error` («تعذّر الوصول إلى النموذج الآن») والمفتاح سليم.
السبب: الطبقة الأساسية في `src/ai/transport.ts` كانت تنادي `client.interactions.create`،
ونسخة `@google/genai` المثبّتة (**2.32.0**) لا تُعرّض `interactions` وقت التشغيل أصلاً —
مفاتيح الكائن هي `models, live, batches, chats, caches, files, …` فقط. أي أن النداء كان
يرمي `TypeError` محلياً قبل أي اتصال بجوجل، والخطأ لم يكن مطابقاً لقاعدة «الواجهة غير
متاحة»، فلم يُسقط إلى `models.generateContentStream` وخرج كما هو.

الإصلاح الآن:

- `interactions` صار **اختيارياً** في نوع العميل، مع `hasInteractions(client)` تفحص
  وجود الدالة وقت التشغيل؛ فإن غابت، ينتقل الطلب مباشرة إلى `generateContentStream`
  ويكتب سطراً في السجل بدل أن يفشل السؤال.
- `isInterfaceUnavailable()` يعتبر `TypeError` و«is not a function» و«cannot read propert…»
  عيوبَ واجهة، لا أعطال شبكة.

وما يجعل التشخيص ممكناً من المتصفح بلا سجلات: `/api/ai/status` يعرض
`lastUpstream: {signal, at}` بثلاث حالات مفصولة — `rate_limited` (٤٢٩، «الحد مؤقت —
جرّب بعد دقيقة»)، `key_rejected`، `model_unavailable` — والرسالة النصية لم تعد واحدة
للجميع.

### السبب الثالث: جوجل نفسها ترفض المفتاح

بعد نشر التصنيف ظهر الجواب من جوجل لا منّا:

```
{"error":{"code":400,"message":"API key not valid. Please pass a valid API key."}}
```

أي أن المتغيّر `GEMINI_API_KEY` موجود على Vercel (`aiKeyPresent: true`) لكن **قيمته**
لم تُعرَف عند جوجل: مفتاح مُلغى (AI Studio تُلغي أي مفتاح يظهر في مستودع عام)، أو نسخة
ناقصة/بها علامة اقتباس. لذلك:

- صار للمفتاح المرفوض كودُه `key_rejected` ورسالة عربية تقول السبب والعلاج، لا
  «تعذّر الوصول إلى النموذج».
- `/api/ai/status` يعرض `keyShape: {length, looksLikeAiStudioKey}` — **الطول والشكل
  فقط، لا المفتاح** — لتمييز لصقة ناقصة من مفتاح مُلغى.
- الحل دائماً: مفتاح جديد من <https://aistudio.google.com/apikey> يوضع في
  Environment Variables ثم Redeploy.

### السبب الرابع: النموذج مزدحم (503) — ومعالجته في السلسلة

بعد وضع المفتاح الجديد (53 حرفاً بصيغة `AQ.…` الحديثة) اختفى `key_rejected` وظهر:

```
This model is currently experiencing high demand. Spikes in demand are usually temporary.
```

أي أن المفتاح سليم، والنموذج `gemini-3.8-flash` على حدّ طاقته في تلك اللحظة. السلوك قبل
الإصلاح كان يفشل السؤال كلّه عند أول نموذج مزدحم. الآن:

- `model_busy` إشارة مستقلة (503) ولها رسالتها: «الخدمة مزدحمة الآن — جرّب بعد دقيقة».
- `runChain` في `src/ai/transport.ts` يعتبر الازدحام وتجاوز الحد سبباً للانتقال إلى
  **النموذج التالي** في السلسلة، لا لإنهاء الإجابة؛ وإن ازدحمت السلسلة كلها ينتظر ١٫٥ ثانية
  ويكرّرها مرة واحدة. المفتاح المرفوض وحده لا يُعاد أبداً.
- `keyShape.looksLikeAiStudioKey` صار يقبل الصيغتين: `AIza…` (39) و`AQ.…` (53).

### السبب الخامس والأخير: SDK يتخلّف عن الواجهة التي تخدمها جوجل

بعد أن صار المفتاح سليماً، ظهر في جسم خطأ جوجل نفسه:

> `This model models/gemini-2.5-flash is no longer available to new users.`
> `… Please update your code to use the Interactions API.`

والمشروع كان مثبّتاً على `@google/genai` **2.32.0**، وهي لا تُصدّر `interactions` أصلاً.
النسخة الحالية **3.6.1** تُصدّره ويعمل. لذلك:

- رُفع الاعتماد إلى `@google/genai@^3.6.1`، وصار مسار `interactions.create` هو الأساس،
  و`models.generateContentStream` احتياطياً فقط.
- أُضيف `GET /api/ai/ping` (و`?api=interactions`) يسأل كل نموذج ١٦ رمزاً ويعيد
  المللي ثانية والسبب وكلام جوجل — به عُرف أن `3.8-flash` استهلك حصته اليومية
  (`retry in 17h…`)، وأن `3.6-flash` يجيب في أقل من ثانية، وأن `2.5-flash` لم يبق
  متاحاً للمفاتيح الجديدة.
- ترتيب السلسلة صار حسب القياس: `3.8-flash` ← `3.6-flash` ← `3.7-flash` ←
  `gemini-flash-latest`، و`TUTOR_MODELS.primary` يبقى قابلاً للتغيير بـ`TUTOR_MODEL`.
- كل نموذج له ١٢ ثانية (`PER_MODEL_TIMEOUT_MS`) قبل أن تنتقل السلسلة، وكل عميل
  (`copilot`/`site-manager`) يجرّب `interactions` بعد فشل المسار القديم.

النتيجة المقيسة على الإنتاج: `.github/workflows/ai-probe.yml` صار **أخضر**، وتعليقه
`tutor answer: deltas=3` — أي أن المستشار يكتب فعلاً، بمصادر غير مُراجَعة من الأكاديمية.

### تصحيحان قياسيان بعد أسبوع من النشر

1. **`gemini-flash-latest` لم يكن على المفتاح أصلاً.** `GET /api/ai/models` صار يعيد
   `missingFromKey: ["gemini-flash-latest"]`، أي أن كل طلب كان يحرق محاولة كاملة على
   404. أُخرج من السلسلتين، وأُقحم بدله `gemini-3.5-flash-lite` — الموديلات الخفيفة
   لها حصة مجانية منفصلة وأكبر، وجواب أقصر أفضل من صمت.
2. **`gemini-4-hydrogen` كان أول السلسلة مع أنه يردّ 503 high demand** في كل قياس.
   صار في آخر السلسلة، والعميل (`copilot` / `site-manager`) يبدأ من `gemini-3.8-flash`.

كذلك صارت السلسلة **ثلاثة أسماء فقط** (أساسي + احتياطيان) حتى تتسع أسوأ حالة
(٣ × ١٨ ثانية) داخل الستين ثانية التي يجوز للفنكشن أن يعمل فيها، وصار الفحص الآلي
ينتظر ٧٠ ثانية بدل ٤٥ كي لا يُسجّل إجابة بطيئة على أنها سكوت.

**الدرس الأهم:** الحصة المجانية اليومية لكل موديل هي السقف الحقيقي. نفس الاستدعاء
قاس ٠٫٩٩ ثانية ثم ٨٫٧ ثانية ثم تعليقاً كاملاً في أقل من ساعتين. المفتاح سليم طوال
الوقت (`/api/ai/models` يعيد ٢٨ موديلاً بلا 401)، والعلاج الوحيد هو تفعيل الفاتورة
على نفس مشروع جوجل أو انتظار تجديد الحصة.



**على GitHub Pages (بلا خادم):** يبقى الموقع صالحاً بالكامل — الكتب والمقررات
والبحث والامتحانات تعمل؛ تبويب المستشار يقول صراحةً إن البوابة غير موصولة،
ولا يطبع إجابة جاهزة.

> مهم: لا تضع `GEMINI_API_KEY` في أي ملف يذهب إلى `docs/` أو `public/`.
> سياسة مفاتيح AI Studio (2026) ترفض المفاتيح المكشوفة، والحزمة الثابتة عامة.

## 11. ما لا يفعله هذا النظام

- لا يصدر شهادات ولا يمنح اعتماداً. الشهادة الموجود في `certificates` هي
  **بيان دراسة ذاتية غير معتمدة**، مستقلة تماماً عن أي استعمال لـ Gemini.
- لا يجيب من خارج مكتبة إنسكو. إن لم يجد مصدراً في المكتبة يسأل عن صياغة أخرى.
- لا يخزّن أسئلة المتدربين (`store: false`).
- لا يعمل بلا مفتاح، وهذا مقصود: صفحة ثابتة بلا بوابة يجب أن تقول ذلك.

### مهلة أول رمز، لا مهلة الجواب كله

فحص حيّ على الدومين (`.github/workflows/ai-live-check.yml`) كشف الحالة الدقيقة: المستشار
بدأ يكتب فعلاً وأرسل ٣٠ مقطعاً، **ثم انتهى الحدث بخطأ `model_busy`** فظهرت للمستخدم
إجابة ناقصة وشريط «الخدمة مزدحمة». السبب أن مهلة النموذج (١٨ ثانية) كانت تُحسب على
الجواب كله، وأي نموذج بطيء كان يُقطع في منتصف الجملة ثم تُنقل المهمة لنموذج آخر.

- المهلة الآن **لأول رمز فقط**: بمجرد أن يبدأ النموذج الكتابة تُلغى مؤقّتته ويكمل تحت
  ميزانية الطلب وحدها (`REQUEST_TIMEOUT_MS` صارت ٥٥ ثانية لأن الفنكشن يجوز له ٦٠).
- نموذج بدأ الكتابة ولا يكمل **لا يُستأنف على نموذج ثانٍ أبداً** — وإلا قرأ المستخدم
  البداية مرتين بصوتين مختلفين.
- `ai-live-check.yml` يشغّل السؤال الحقيقي (POST على `/api/ai/tutor` والكوبيلوت) من أي
  فرع، وينشر النتيجة كتعليقات على الـrun، لأن سجلات الـrunner لا تُنزَّل
  (`gh run view --log` يعيد EOF). `ai-probe.yml` يبقى بوابة الدمج على `main`.

### الاستئناف: حين تقطع جوجل الرد في منتصفه

القياس الحيّ بعد إصلاح مهلة أول رمز أظهر أن القطع ليس من عندنا: النموذج كتب ١٢ مقطعاً
ثم أنهت جوجل التفاعل بخطأ `high demand`. الحصة المجانية لا ترفض الطلب من أوله دائماً،
بل تسمح له بالبدء ثم تقطعه.

- صار الخادم **يستأنف** الرد: يعرض على النموذج ما كُتب حتى الآن ويطلب إكماله من حيث
  توقف دون تكرار ودون مقدمة جديدة، مرتين كحد أقصى، وبشرط بقاء ٨ ثوانٍ على الأقل من
  ميزانية الطلب. إن انتهت الميزانية تبقى الإجابة الجزئية ويُشرح السبب.
- **الوكلاء (copilot / site-manager) صاروا يبدأون بـ`interactions`**: كانوا يجرّبون
  `models.generateContent` أولاً (المسار المسحوب) فيستهلك كل نموذج ١٨ ثانية صامتة قبل
  أن تُجرَّب الواجهة العاملة — وهذا سبب 504 المتكرر. المسار القديم بقي احتياطياً أخيراً
  وبمخرج أقصر (١٤٠٠ رمز) حتى يكتمل الـJSON داخل المهلة.
